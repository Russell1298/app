Scope & Methodology
What was tested, how, and what is out of scope
This assessment is read-only and non-intrusive. Nothing was modified on the target and nothing was installed. No authentication was attempted and no exploit code was executed. Three of the nine modules are fully passive and never contacted the target: DNS and email record lookups and DNS hijack detection both queried public resolvers, and subdomain discovery read public certificate transparency logs. The remaining modules sent ordinary HTTPS requests. One module, Public Exposure, requested a fixed list of 18 common file and directory paths to determine whether any were publicly reachable; those requests may appear in the target's access logs and a web application firewall may record them as a scan. All findings are based on publicly observable information only.

Modules Run
Security Headers
Checks HTTP response headers for missing or misconfigured security controls (CSP, HSTS, X-Frame-Options, etc.).
DNS & Email
Reads DNS records through public resolvers and checks SPF, DMARC, CAA, and other email authentication controls.
SSL / TLS
Evaluates the certificate chain, expiry date, supported TLS versions, and self-signed status.
Public Exposure
Requests 18 common sensitive paths (.git, .env, admin panels, debug endpoints) once each. Where a path responds, the opening bytes of the body are read to rate confidence. File contents are not stored.
Subdomain Discovery
Queries the public certificate transparency log (crt.sh) for known subdomains and verifies DNS resolution.
Secret Exposure
Reads the homepage HTML and up to five linked JavaScript files, looking for published credentials and API keys. Matches are redacted before storage.
Fingerprinting
Identifies server software, CMS, frameworks, and CDN from headers, cookies, and page content.
Checkout Scripts
Inventories third-party JavaScript loaded on the homepage and checkout pages and checks each script for integrity protection.
DNS Hijack Detection
Compares answers from three independent public DNS resolvers to detect tampering, and checks whether DNSSEC signs the domain's records.
Out of Scope
This report excludes: authenticated scanning, brute-force attempts, exploit testing, social engineering, physical security, internal network assessment, and manual code review. Findings reflect publicly observable signals; exploitability was not confirmed. For a full penetration test, engage a certified security professional.

The full method for every module, including exactly what each one sends, is published at {{ company.methodology_url }}.
